# "AGRICHARTS" ON NOTHING BUT A WEATHER WIDGET -- 2026-09-14

# 119 sites. data/platforms.json files each of them platform=agricharts,
# adapter=null, and the ONLY evidence behind that verdict is that the home page
# calls Barchart's /weather/translate or /weather/forecast. Not a cash board.
# Not a price. The weather.
#
# HEARTLAND CO-OP IS WHY THIS LIST EXISTS. Its entry said agricharts on those
# same two endpoints. Its board is not AgriCharts and never was: it is a
# server-rendered matrix at https://myaccount.heartlandcoop.com/bids.htm, read
# on 2026-09-14 by probe run 94223494234, and it carries 129 rows across four
# commodity tables -- 48 of the 48 Heartland facilities the Barchart roster
# holds, plus six the roster does not have. lib/adapters/heartland.mjs reads it.
#
# discover.mjs COULD NOT HAVE FOUND IT. Its board-page follower refused any link
# leaving the home page's host, and "myaccount.heartlandcoop.com" is a different
# host from "heartlandcoop.com". registrable() fixed that on 2026-09-13; these
# 119 have not been asked since.
#
# AND NO EXISTING BUTTON WILL ASK THEM. Every sweep runs discover --resume,
# which skips a site whose status is "platform" -- "finding a board is not made
# wrong by looking harder", which is true and is not what happened here. These
# were decided by a probe that could not see the subdomain the board was on.
#
# THIS IS A MEASUREMENT, NOT A CLAIM. Some of these almost certainly do run
# AgriCharts: it is Barchart's own website product and the weather widget ships
# with it. The claim is narrower and it is about the BOARD, not the site: the
# weather endpoint says nothing about where the prices are, and on one site out
# of one checked so far it was somewhere else entirely.
#
# discover.yml writes nothing (permissions: read), so asking this list costs a
# log and changes no record. Actions -> discover -> list = weather-only.
